Pikslar 0.9.0-beta.1: third-party notices
=========================================

Pikslar's own source uses no third-party libraries ("crates"). The program files
pikslar.exe and pikslar-cli.exe nevertheless contain code that was not written
for Pikslar, put there by the Rust compiler and the linker. This file lists it.

How this was determined
-----------------------

Both release program files were linked with a GNU ld link map (-Wl,-Map) on
2026-11-21 (at commit f885ee0; see docs/b1-packaging.md), with the pinned linker described in
BUILD.txt: WinLibs GCC 16.2.0 with MinGW-w64 14.0.0 (UCRT), link-self-contained=no.
The map lists every object file and every archive member the linker took.
Besides Pikslar's own code and the Rust standard library, it took only:

  From the MinGW-w64 runtime (mingw-w64-crt 14.0.0):
    crt2.o                                program start-up
    libmingw32.a: CRT_fp10, _newmode, cinitexe, crt_handler, dllargv,
      gccmain, merr, mingw_helpers, natstart, pesect, pseudo-reloc,
      pseudo-reloc-list, tlsmcrt, tlssup, tlsthrd, usermatherr, wildcard,
      xncommod, xthdloc, xtxtmode
    libmingwex.a: mingw_matherr
    libmsvcrt.a (UCRT variant): __initenv, __p___initenv,
      ucrt___local_stdio_printf_options, ucrt__getmainargs, ucrt_amsg_exit,
      ucrt_fprintf, ucrt_vfprintf, and import stubs for the Universal CRT
      (api-ms-win-crt-*.dll, part of Windows)
  From GCC 16.2.0's runtime library (libgcc):
    crtbegin.o, crtend.o, libgcc.a: _ctors, libgcc_eh.a: unwind-seh

pikslar-cli.exe takes the same members except a few Universal CRT math import
stubs. Import stubs for Windows' own DLLs (kernel32, user32, gdi32 and so on)
only name functions in Windows and carry no third-party code.

No MinGW-w64 or GCC DLL is needed at run time: the import table of each file
(checked by the release script) names only Windows system DLLs and the
Universal CRT.

4. Blending arithmetic from Aseprite and pixman
-----------------------------------------------

Pikslar's "Aseprite-compatible" blending (crates/pikslar-core/src/
blend_straight.rs and blend_hsl.rs) follows the formulas and rounding of
Aseprite's src/doc/blend_funcs.cpp (Aseprite commit 9cf3c128), which is
released under the MIT licence, and the integer helpers MUL_UN8 and DIV_UN8
that Aseprite takes from the pixman library, which is released under an
MIT-style licence. Pikslar's code is its own Rust, but because it follows
that code closely, both notices are included: the verbatim licence file of
Aseprite's src/doc folder and pixman's COPYING file follow after this section.

The texts of the MIT licence, the Apache License 2.0, the Unicode License v3,
the GCC Runtime Library Exception 3.1 and the GNU GPL version 3 follow after
those.
