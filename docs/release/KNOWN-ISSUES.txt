Pikslar 0.9.0-beta.1 known issues
=================================

What is known to be wrong, missing or untested in this beta. Items marked
"may be fixed before release" have a fix planned; if it lands, this list is
updated with the build that has it.

All testing so far was automated, on one computer: Windows 11 Home build
26200, 2560 x 1440 at 100 % scale, Norwegian keyboard layout. Keys and mouse
movements were sent to the program by scripts; no physical keyboard, mouse
or pen was used in any check.


1. Saving and reliability
-------------------------

1.1 An unexplained saving stop in a long test (the "minute-276" incident)

What happened. In an 8-hour automated test of an earlier build (ac9fb2f,
2026-11-20), the program stopped saving at minute 276. The window kept
answering, memory and other resources stayed flat, and the test kept sending
input, but no save and no change happened for 5 minutes, so the test failed.
That test kept no record of what was on screen.

What was found. Investigation showed one way to produce exactly this state:
when the program's window paused for more than about 5 seconds, the test's
own input could turn a plain E key into Ctrl+E, which opened the Export
dialog. That dialog then took every key, including Ctrl+S, and gave no
message, and the test never closed it. This was reproduced 10 times out of
10 with a deliberately injected pause. Windows' logs show the computer's
session waking from keyboard or mouse input about a minute before, but no
log shows the program actually pausing at that moment, or why it would.

What is not known. The root cause of the original incident is NOT
established. The mechanism above fits the evidence, but it was not shown to
be what happened, and other causes have not been ruled out.

What changed. Ctrl+S is never ignored silently any more: if a dialog, menu
or name field is in the way, the status bar says "Not saved: ..." and what
to do. The status bar always shows whether work is unsaved, saving, saved,
blocked or failed. No wait on the window is unbounded. The test harness was
corrected so it cannot misread keys this way, and it now records any
moment it had to wait too long, resend a key or rescue the program, which
fails the test. Diagnostics (README.txt) now record saving events, so a
repeat would leave evidence.

What passing tests do and do not show. Long tests passing on this build
would show that it ran stably under the corrected test, not that the
original cause is gone. If you ever see saving stop without a "Not saved"
or "Save failed" message, please report it (TROUBLESHOOTING.txt).

1.2 Changes made by another program in the last moment before a save

A project changed by another program is detected before saving over it.
Two small gaps remain: a program that replaces the file by renaming another
file over it in the few milliseconds between Pikslar's last check and its
replace can still be overwritten; and on FAT and exFAT drives (many USB
sticks and memory cards), Windows keeps file times only to 2 seconds, so a
change of the same size within 2 seconds of the remembered time is not seen.
NTFS drives keep times to a ten-millionth of a second.

1.3 Storage that has not been tested

Network drives, OneDrive and other sync folders, USB drives and memory
cards, FAT or exFAT drives and a really full disk have not been tested.
Saving is atomic only as tested, on a local NTFS drive. A full disk was only
simulated.

1.4 Recovery copies

A recovery copy is written about 8 seconds after a change, so a crash can
still lose the last few seconds. A scale still being dragged is not in a
copy until the mouse button is released. Sign-out, restart and shutdown
were tested by sending Windows' messages to the program, not by really
signing out.


2. Windows versions, settings and hardware
------------------------------------------

2.1 Windows 10 has not been tested at all. No Windows 10 computer or
virtual machine was available. From reading the code: it should start on
Windows 10 version 1703 or later, 64-bit (x64) only; on 1703 to 1803 the title bar is expected
to stay light above the dark interface (the dark title bar needs a later
Windows 10 update; the rest of the window is not affected).

2.2 Windows 10 before version 1703, Windows 8.1 and Windows 7 cannot run
Pikslar. From reading the code, Windows itself is expected to refuse to
start it, with its own error message (for example about a missing entry
point), before Pikslar can say anything. Not tried.

2.3 Real Windows display scaling (125 % to 300 %), high contrast and text
size settings have not been tested. They were imitated with Pikslar's own
test switches, which use the same code but not Windows' own behaviour.

2.4 Other keyboard layouts (US, UK, German, French and others) have not been
tested on real keyboards. From reading the code:
- French and Belgian AZERTY: "next frame" (the . key) cannot be reached,
  because that key types ; without Shift. May be fixed before release.
- Nordic and German keyboards: Shift with the < key (which types >) moves
  to the PREVIOUS frame, not the next. May be fixed before release.
- Shortcuts follow the letter printed on the key, so on QWERTZ and AZERTY
  undo is the key marked Z, as in other Windows programs. Letter and digit
  shortcuts can be changed in View, Keyboard shortcuts.

2.5 Sleep, resume, screen lock and monitors being removed while Pikslar is
open have not been tested, and the program does not react to them
specially. From reading the code: redrawing should be fine; a window left
on a monitor that was removed may stay partly off screen until moved
(Alt+Space, then Move). May be fixed before release.

2.6 Other computers, graphics, laptops, monitors at mixed scaling, Windows
on ARM, standard (non-administrator) accounts, managed work or school PCs
and antivirus programs other than Microsoft Defender have not been tested.

2.7 Screen readers are not supported. Pikslar draws its own interface and
does not yet expose it to Narrator, NVDA or JAWS.

2.8 Pen tablets are not supported specially: there is no pressure or tilt,
and a pen works only as Windows turns it into mouse input. Not tested.

2.9 Touch screens and touchpad gestures have not been tested.


3. The program package
----------------------

3.1 Not signed. Windows SmartScreen warns on first start, and computers with
Smart App Control turned on cannot run Pikslar at all. See
TROUBLESHOOTING.txt. Never turn these protections off for Pikslar.

3.2 pikslar.exe is larger than its own size target: 2,826 KiB at build
be1f9f2, against a soft target of 2,816 KiB. This was a deliberate choice:
the crash and saving diagnostics were kept rather than removed to save
space. It has no effect on use.

3.3 The licence (PolyForm Noncommercial 1.0.0) allows noncommercial use
only; commercial use needs separate permission (LICENSE.txt).

3.4 Reproducible builds were checked on the development computer only.


4. Performance
--------------

Three measurements have been over their limits since before this beta. They
are unchanged and reported in every run; no limit was relaxed:
- Undoing and redoing 2,000 steps: 107.5 microseconds against a limit of
  105.1.
- The largest tile cache in the stress test: 3,073,536 bytes, over its
  limit.
- Stepping a frame of the stress tile map: 9.02 ms against a limit of 4 ms.

All figures are from the development computer. Slower computers will be
slower.


5. The interface
----------------

5.1 In the Draw workspace at interface size 2x with Large text, the Palette
panel is folded to its strip for lack of room. Click its strip to open it.

5.2 Large text set to automatic is applied when Pikslar starts, not when
Windows' text size changes while it runs. In Large text the right-hand
panels fold to a rail one step earlier.

5.3 Controls do not grow with Large text; only the words do.

5.4 The canvas is not refitted when you change workspace (for example,
Animate at 1x leaves about half the window to the canvas). Use Fit (0).

5.5 Not built yet: the Sprite, Layer, Frame, Select and Help menus; dragging
a panel's tab to dock it elsewhere; naming a custom workspace; separators in
every menu.

5.6 The Export dialog uses separate option buttons where the selection bar
uses a joined control, and the empty Tags row always takes its space.

5.7 The Pixel Lint tab's icon is a warning triangle, which can read as a
warning when there is none.

5.8 The interface was judged on screenshots of small documents and a few
pieces of original art; very many layers and long timelines have not been
judged.


6. Features with known limits
-----------------------------

6.1 Aseprite import is read-only and experimental. Files from real projects
may differ from what Aseprite shows; a diagonal flip on a tile that is not
square cannot be kept and is reported.

6.2 Scripting and plugins are experimental. Script speed limits were set on
the development computer, so a slower computer stops a runaway script later.
A plugin's fingerprint detects changes to its files, but does not prove who
made it.

6.3 Rewind (off unless turned on) was tested on one computer and one disk.
It keeps the undo side of history, not redo or selections. Its store finds
damage but is not protected against deliberate tampering.

6.4 Right-to-left text, combining marks and emoji sequences are not handled
in names.


7. Not verified by any person
-----------------------------

No person outside development has used this version. Usability, comfort
and how well features can be found have not been tested with real artists.
